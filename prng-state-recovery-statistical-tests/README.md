# PRNG State Recovery and Statistical Randomness Tests

## Overview

A from-scratch study of why non-cryptographic generators must not be used for secrets. The package implements four generators (MT19937, xorshift128+, a general LCG and `java.util.Random`), the attacks that recover their internal state from a handful of outputs, and a NIST-style battery of statistical tests that shows which weaknesses are visible statistically and which are not. Pure Python + NumPy.

## How the algorithms work

- **MT19937 cloning.** The output tempering is a composition of invertible xor-shift/mask steps, so `untemper` recovers each raw state word. 624 consecutive outputs give the whole state, after which every future output is predictable.
- **MT19937 rewinding and seed recovery.** The twist `new[i] = new[i+397] ^ (y>>1) ^ (A if y&1)` can be run backwards word by word (the top bit of the twisted value reveals `y&1`). One block is recovered except for the 31 low bits of word 0, which never influence the next block. Applied to the first output block this yields the `init_genrand` state; inverting `s1 = 1812433253*(s0 ^ s0>>30) + 1` gives the 32-bit seed, verified against the remaining 623 words.
- **xorshift128+ from least-significant bits.** The state update is linear over GF(2) and the low bit of a sum has no carry, so each output LSB is an XOR of known state bits. Symbolic tracking of the 128 state bits as bitmasks gives one equation per output; Gaussian elimination over GF(2) (rows as Python integers) recovers the 128-bit state from about 128 bits, and the full 64-bit outputs follow.
- **LCG parameter recovery.** From raw states, the gcd of `t[i+2]·t[i] − t[i+1]²` (with `t[i]=x[i+1]−x[i]`) yields the modulus; then `a = (x2−x1)/(x1−x0) mod m` and `c = x1 − a·x0`.
- **Truncated LCG (java.util.Random).** With a known power-of-two modulus and output `state >> k`, the `k` hidden low bits of the first state are enumerated (vectorised in NumPy) and filtered against later outputs. Two 32-bit outputs of the 48-bit Java generator leave a unique candidate.
- **Statistical battery.** Monobit, runs, block frequency, byte chi-square, serial (overlapping 3-bit), autocorrelation (lags 1, 2), spectral (FFT) and a Berlekamp-Massey linear-complexity test, with p-values from an in-house regularised incomplete gamma function and `erfc`.

## Complexity

| Procedure | Time | Space |
|---|---|---|
| MT19937 clone | O(624) | O(624) |
| MT19937 rewind / seed recovery | O(624) | O(624) |
| xorshift128+ recovery (n ≥ 128 bits) | O(n · 128) for equations, O(n · 128) for elimination with big-int rows | O(n) |
| LCG modulus/parameters (n states) | O(n) gcds | O(n) |
| Truncated LCG, k hidden bits, n outputs | O(2^k · n) | O(2^k) |
| Berlekamp-Massey (n bits) | O(n · L) | O(n) |
| Frequency/serial/spectral tests | O(n) – O(n log n) | O(n) |

## Usage

```python
from prng_attacks import MT19937, clone_mt19937, Xorshift128Plus, recover_xorshift128plus

victim = MT19937(1234)
seen = victim.outputs(624)
clone = clone_mt19937(seen)
assert clone.next_u32() == victim.next_u32()

xs = Xorshift128Plus(0x9E3779B97F4A7C15, 0xBF58476D1CE4E5B9)
gen = recover_xorshift128plus([o & 1 for o in xs.outputs(160)])
assert gen.next_u64() == xs.next_u64()
```

Run `python examples/demo.py` for the full walk-through and `python -m pytest -q` for the tests (25 tests).

## Results

Output of the demo (times on a CI machine):

| Attack | Input | Outcome | Time |
|---|---|---|---|
| MT19937 clone | 624 outputs | next 1000 outputs predicted | 2.1 ms |
| MT19937 seed recovery | first 624 outputs | seed 31337 recovered | 2.7 ms |
| MT19937 rewind | 624 outputs | 623/623 earlier outputs reproduced | – |
| xorshift128+ | 160 output LSBs | full 64-bit outputs predicted | 10.3 ms |
| LCG (m, a, c) | 40 states | parameters recovered exactly | – |
| java.util.Random | 2 outputs | next outputs predicted | 2.2 ms |

Statistical battery (9 tests, α = 0.001):

| Stream | Tests passed | Failed |
|---|---|---|
| MT19937 full words | 9/9 | – |
| MT19937 LSB | 9/9 | – |
| xorshift128+ full words | 9/9 | – |
| xorshift128+ LSB | 7/9 | spectral, linear_complexity |
| LCG(2^32) LSB | 2/9 | runs, byte_chi_square, serial, autocorrelation, spectral, linear_complexity |
| java.util.Random LSB | 9/9 | – |

The point of the second table: MT19937, xorshift128+ and `java.util.Random` pass most statistical tests yet are completely predictable, while a weak low bit is visible immediately for power-of-two LCGs.
